# Benchmark and ablation protocol

## Design

The saved ablation artifact contains four configurations, 60 distinct seeds and five outer species folds, with six traits × two bounds per configuration and seed. It corresponds to the historical 170-species workbook; new runs default to `FernTraits.xlsx` (189 taxa with recorded min/max traits) and cannot be combined with those results. The configurations are `no_env_no_phylo` (Base), `env_only`, `phylo_only` and `env_phylo` (full). Paired comparisons should match seeds, folds, evaluation cells, preprocessing, masks and outputs. These repeated splits overlap and are not independent samples of species.

The paper compares training mean, training median, phylogenetic nearest neighbour and five-neighbour mean, R MICE with CART, Rphylopars with Brownian motion and diagonal phylogenetic covariance, and tuned random forest, XGBoost and MLP regressors (Methods, Table 1 and the appendix table `tab:ml_hyperparameters`). Tree-dependent baselines cannot predict taxa missing from tree tips: current exports retain these rows with missing predictions. Comparisons between the GNN and the baselines are therefore scored only on the species common to all compared methods, which must be exactly the taxa present in the reconstructed tree (182 of 189); see [analysis conventions](analysis-conventions.md). The GNN is still trained on all 189 taxa, and GNN-only analyses (ablation, attribution) keep all taxa. The Rphylopars wrapper normalizes quoted Newick tip labels to match the species names consistently with the Python tree reader. Current baseline protocol 1 fits using outer-training species, then masks a target group for all test species and transforms the test data; protocol 2 fits on the training plus masked test table and is transductive. `r_baselines_fit.py` defaults `OPENBLAS_NUM_THREADS` to 1 (overridable by exporting it): `mice::remove.lindep` calls `eigen()` for every imputed variable and iteration, and with threaded OpenBLAS on a shared machine one `m = 1`, `maxit = 1` MICE fit of fold 0 (151 × 118 table, environmental and phylogenetic columns) took 250 s instead of 7 s. MICE runs `m = 5` chained imputations and is scored on their mean (`r_models.pool_completions`, the Rubin's-rules point estimate) in both protocols; until 2026-11-25 only the first completed dataset was scored, so earlier MICE results are single random draws. **Known open defect:** on fold 0 the current MICE baseline drops `SporeMax` as collinear with `SporeMin` (driven by extreme training spore values), removes many predictors through `remove.lindep`, and imputes test rows in a single chained pass. It reversed 123 of 224 evaluated (min, max) pairs and its stipe/frond errors were about twice RF's. MICE results from the current code should not be interpreted until this is resolved; see the [log](../log.md). MICE's wrapper calls `mice.mids(newdata=...)`; whether this re-estimates conditional models with test rows needs independent verification before treating it as an immutable trained CART predictor. The historical (published) comparison did not include an equal-input conventional ML predictor. The code provides tuned random forest, XGBoost and MLP baselines with matching species-level inputs, now described in the manuscript; see [ML baselines](../updates/ml-baselines.md). The runner schedules these models and MICE for all four environmental/phylogenetic input combinations; trait/tree-only reference methods run once per seed. Full new results remain pending.

## Run current code

Install dependencies as in [README](../../README) and use the R environment for baselines. Example for a fresh exploratory benchmark:

```sh
.venv/bin/python run_benchmark.py 1 --start-seed 42 --occlusion-protocol paired --output-dir benchmark_paired_new
```

To run complete seed suites concurrently, set `--parallel-seeds` (for example, `--parallel-seeds 3`). Each worker runs four supported baseline input configurations and four GNN configurations for one seed. Both baseline and GNN subprocesses activate the R environment, since graph loading reconstructs the tree through rpy2. Aggregation starts only after every requested seed suite has completed and its expected outputs have been checked; it includes exactly the requested seed range and all available contributions for those seeds. If any job fails or an expected output is missing, the run stops before writing aggregates and can be resumed with the same arguments.

This is one seed with five folds, four GNN configurations, selected baselines and XAI; it is not a reproduction of the historical 60-seed result. The orchestrator accepts a common `--split-strategy` and no separate program arguments. It records the protocol, model configurations, Python package versions, source-code hashes (including `ml_baselines.py`) and the R, R-package and FTOL-data versions resolved by the `r-baselines` environment in a resume-checked manifest, along with workbook, tree-script and project R-library (`.local/r-library/*/DESCRIPTION`) fingerprints. Use a different empty output directory for each study; external spatial inputs are not yet captured by the manifest. Grouped genus and tree-derived clade splits are available for separate sensitivity studies. Benchmark defaults turn on XAI and a complete run can be expensive.

The optional `<output-dir>/hyperparameters.yaml` supplies fixed parameters per ML model and trait, shared across input configurations. When present it replaces inner randomized search and its SHA-256 is checked in the manifest. The file prepared on 2026-11-26 selects the most frequent complete parameter set in available `tuning.csv` records (ties resolved by sorted JSON); its votes are recorded in the file. Because the selection used the same repeated evaluation splits, subsequent results using it are exploratory, not independent estimates. The earlier run and its manifest were moved to `.soft_del/2026-11-26-pre-fixed-hyperparameters/`; no prior results were relabelled.

## Artifacts

Every model writes the same per-fold files on the **original measurement scale**: `predictions_min.csv` and `predictions_max.csv` (wide, after the min ≤ max projection), `predictions_long.csv` (one row per species × trait × bound with `observed`, `predicted`, `evaluated` and `scale = original`), `bounds_order.csv` and its metric file (`per_trait_metrics.csv` for baselines, `per_trait_metrics_original.csv` for the GNN). The GNN additionally keeps its network outputs as `predictions_{min,max}_normalized.csv`; these are fold-specific and must not be compared across folds or models. Each model directory merges folds into `predictions_{min,max}_all.parquet` (indexed by species) and `predictions_long_all.parquet`, and every run directory contains `ftol_mapping.csv` (FTOL placement and `in_tree` per taxon). GNN and ML baselines map transformed predictions back to this scale with the same bounded inverse (`prediction_bounds.bounded_inverse`; see [ML baselines](../updates/ml-baselines.md)). Exports fail at the fold that produces non-finite evaluated predictions. The benchmark refuses to aggregate a model whose long export is missing, not on the original scale, or has non-finite evaluated predictions, and writes merged `predictions_min_all.parquet`, `predictions_max_all.parquet` and `predictions_long_all.parquet` per configuration.

Historical runs differ: their GNN `predictions_min.csv`/`predictions_max.csv` are normalized outputs, and original-scale values are in `predictions_*_original.csv` and `predictions_original_all_folds.csv`. They have no long exports and cannot be loaded by `analysis_utils.py`. The consolidated `results_ablation.parquet` is built by `ablation_extractor.py` from fold metric files using `benchmark_analysis.py`. Confirm data, exact code version and parameters for any historical run; folder names alone do not establish provenance.

GNN and ML model folds additionally write `prediction_safeguards.csv` with per-output correction counts; GNN logs distinguish calibration and test. Statistical/R methods do not apply this inverse-transform policy. See [prediction safeguards](../methodology/prediction-safeguards.md). The source manifest includes `prediction_bounds.py`, preventing resumes across changes to this shared policy.
